# Test Critic

[English README](README.md) · [Участие в разработке](CONTRIBUTING.md) · [Безопасность](SECURITY.md)

Независимый ревьювер написанных тестов для AI-агентов. Проверяет, отличает ли тест
важное правильное поведение от правдоподобного дефекта, и требует конкретных
исправлений вместо формального покрытия. Подходит для backend, web, мобильных
и настольных приложений, CLI и библиотек.

## Установка

Через [skills CLI](https://github.com/vercel-labs/skills):

```bash
npx skills add letya999/test-critic --skill test-critic
```

Команда использует ветку разработки `dev`. Для стабильной ветки `main`:

```bash
npx skills add https://github.com/letya999/test-critic/tree/main --skill test-critic
```

Добавьте `--agent codex` или `--agent claude-code` для выбора агента, `--global` —
для установки пользователю. Изучите инструкции перед использованием. Платные
сервисы, MCP, тестовый раннер и отдельная система оркестрации скиллу не нужны.

## Использование

```text
Используй $test-critic для ревью новых тестов перед запуском.
Проверь, что retry-тест ловит отсутствие ключа, а не проверяет собственный мок.
Проверь диагностику падений, изоляцию и соответствие тестов реальным требованиям.
```

Порядок: проектирование сценариев → написание тестов → ревью → исправления автора
и повторное ревью → разрешённый проектом запуск/TDD. Проектирование выполняет
test-designer, если он используется. Критик не пишет тесты, не меняет приложение,
не запускает и не импортирует тесты, не устанавливает инструменты и не делегирует.
Отдельный контекст организует внешний workflow: самопроверка автора в прежнем
контексте не считается независимым ревью.

## Что проверяется

- Источник ожидаемого результата: реальное требование, контракт, проверенный пример
  или обоснованное свойство; противоречия требований сохраняются для решения владельцем.
- Реальный путь исполнения, достижимость условий, различающие данные и assertions;
  отсутствие пустых сравнений, копирования реализации и мокирования самой проверяемой логики.
- Значимые результаты и запрещённые эффекты: wire-контракт, состояние хранилища,
  права, события, восстановление и общие бизнес-инварианты в рамках изменения.
- Правдоподобный дефект и точное утверждение, которое должно его обнаружить;
  ошибка импорта или подготовки не считается доказательством чувствительности.
- Управляемые время и случайность, порядок, конкуренция, изоляция ресурсов,
  завершение асинхронной работы и доставка фоновых ошибок раннеру.
- Полезная диагностика: идентификация сценария, ожидаемое и фактическое значение,
  сохранение первичной ошибки при очистке. Достаточные стандартные diff не требуют сообщений.
- Отбор раннером, корректность фикстур, стоимость и необходимость тестов;
  дубли удаляются с сохранением существенной защиты.

Моки границ, snapshots, smoke-тесты, несколько assertions и разные уровни
проверок допустимы, если они действительно защищают заявленное поведение.

## Решения и ограничения

| Решение | Значение |
|---|---|
| ACCEPT | В пределах статического ревью существенных проблем не найдено; можно перейти к следующему разрешённому шагу. |
| REVISE | Подтверждённый дефект теста или существенный пробел требует исправления автором и повторного ревью. |
| BLOCKED | Для решения отсутствует важный исходник, требование или обязательная возможность ревью. |

ACCEPT не означает, что тесты прошли или приложение корректно. Статическое ревью
не доказывает отсутствие флаков или реальное падение на дефекте. Предоставленные
логи анализируются отдельно с учётом версии, выбранного теста и причины падения;
зелёный запуск после retry не доказывает стабильность. Markdown-инструкции не
являются техническим перехватчиком команд.

## Разработка и публикация

`dev` — default-ветка. Изменения: `feature → dev → main`; защищённая `main`
принимает только PR из `dev` этого репозитория. Проверки и правила — в
[CONTRIBUTING.md](CONTRIBUTING.md), инструкции агентам — в [AGENTS.md](AGENTS.md).

```bash
python scripts/validate.py
python -m unittest discover -s scripts -p 'test_*.py' -v
python scripts/validate.py --package
```

Для служебных скриптов нужен Python 3.12+; сам скилл runtime-зависимостей не имеет.
Архив `dist/test-critic.skill` содержит инструкции, references, метаданные и лицензию;
документация разработки, evals и локальные результаты туда не входят.
CI проверяет структуру, ссылки, фикстуры, архив и служебные тесты; Gitleaks ищет
секреты, CodeQL анализирует Python/Actions, Dependabot обновляет Actions.
Результаты проб и ограничения: [первичная проверка](evals/validation.md),
[проверка улучшений](evals/revision-validation.md). Структурная проверка не доказывает
эффективность ревьювера, а небольшой benchmark — его превосходство над базовой моделью.

Для [skills.sh](https://skills.sh/docs/faq) достаточно доступного SKILL.md и установок
через CLI: каталог учитывает телеметрию установок. Публикация сама по себе не
гарантирует появление или позицию в рейтинге.
